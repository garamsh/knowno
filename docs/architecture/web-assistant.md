# Web assistant

The web's `assistant` feature: 말랑이's chat at `/assistant`, the conversation kept in the browser, the routes and the actions it reaches the `assistant` function through, its states, its photos and their job, and its one entry, 홈's mascot, with the day's bubble over it ([ADR 0248](adr/0248-meet-malangi-on-home-alone-offer-the-chat-once-a-day-in-a-bubble-over-the-mascot-and-open-it-naming-no-note.md)). The function itself is [`assistant.md`](assistant.md)'s; the shell and the server reads every feature makes are [`web.md`](web.md)'s.

## Current decisions

### Page and layout

- `/assistant`, in the `(shell)` route group and titled "말랑이 · 알아몰라", reads `assistant_allowance()`, the day's tokens left, and draws `AssistantChat`, whatever its query ([ADR 0200](adr/0200-chat-with-malangi-on-the-web-in-an-assistant-feature-streamed-through-a-route-handler-kept-in-the-browser-beside-the-side-menu-from-1024-px.md)); while it reads, a skeleton of the chat's bar and field says "말랑이를 불러오는 중이에요.".
- Below 1024 px the chat covers the screen, the tab bar included, as the phone's pushed chat; from 1024 px it fills the space beside the side menu, which stays. Its turns and field sit in the 720 px `study` column, below a photo import's bar where one shows.
- Its bar: "뒤로", the browser's back or 홈 where there is no history; the mascot at 40 px, still, thinking, sleepy once the day's tokens are used, sad on a failure, happy once a proposal is added; "말랑이" over "오늘 n% 남았어요", the share of the plan's budget left, none without a budget; and ⋯ ("대화 메뉴", `design`'s `RowMenu`) with "대화 지우기", which asks "대화를 지울까요?" before clearing.
- The chat draws no other mascot: the empty chat says "무엇을 외워 볼까요?".
- Opened from 홈 alone ([ADR 0248](adr/0248-meet-malangi-on-home-alone-offer-the-chat-once-a-day-in-a-bubble-over-the-mascot-and-open-it-naming-no-note.md)), the chat names no note: each message carries `context: {time_zone}`, the browser's IANA name from `Intl.DateTimeFormat().resolvedOptions().timeZone` (`browser-time-zone.ts`), which the assistant counts the study day in ([`assistant.md`](assistant.md) §Requests); the zone is read in the browser and travels in the body the route forwards unchanged, never the server's own, and a message with no zone sends no `context`. A stored conversation that holds a "{name} 노트에서" line from before still shows it and never sends it as a turn.

### Conversation

- One conversation, kept in this browser's `localStorage` under `knowno.assistant` with the draft (#711 decision 4); the message list's scroll is kept in `sessionStorage`, so back from a note lands on the same turns, place and draft. A reply stored while it streamed reads back as stopped. Storage that cannot be read starts an empty chat.
- A message sends the last 40 turns, each reply with the proposals it showed, the question it asked and the photo job it started, each user turn with the photos it attached (`assistant.md` §Requests). Enter sends and Shift+Enter breaks the line, a syllable being composed keeping its Enter; a message is at most 4,000 characters.
- 말랑이's text streams in as it arrives, drawn as Markdown in a bubble of its own at the start of the line, up to 92% wide, on `surface` under a `hairline` border as the user's turn, plain text, is at its end ([ADR 0227](adr/0227-draw-malangi-s-reply-as-markdown-with-gfm-in-a-bubble-on-the-web-through-react-markdown-and-remark-gfm-loaded-as-a-chunk-of-its-own.md)); its sources are listed under it once each.
- The function's `interim` event says every `text` since the previous one, or since the turn began, was interim ([`assistant.md`](assistant.md) §Stream, [ADR 0224](adr/0224-mark-the-text-before-a-tool-call-as-interim-with-an-interim-event-and-tell-the-model-to-give-one-reply-a-turn.md)). The turn then holds that text as one line, `AssistantTurn.interim`, with its whitespace folded to single spaces, and its `text` starts again: each new interim replaces the line, and the line goes when the reply's text begins or the turn ends, however it ends. The call's text before its mark streams into the reply view as it arrives and moves to the line when the mark does; the text is not delayed to avoid that (ADR 0224). A reply's leading whitespace is dropped, which drops the separator the function sends before a call's text. The line is drawn under the turn in the place of "말랑이가 생각하는 중이에요", in the same `aria-live="polite"` region (`role="status"`), cut to one line, so a screen reader reads it when it changes and not on each delta. It is read with the reply's parser and extension set (`ReplyLine` in `components/reply-markdown.tsx`, `react-markdown` with `replyRemarkPlugins`, a plugin folding the tree to one text node) as its words without marks: bold, italic, strikethrough and code as their text, a link as its text, an image as its alt text, a table's cells and a list's items in a row; the chunk is the reply's, and the waiting words show until it has arrived. The line is never stored and never sent back, so a stored or sent turn holds the reply alone; a turn of one call has no interim and is drawn as before. The phone does the same ([`assistant-app.md`](assistant-app.md)).
- The Markdown is CommonMark with GFM, read by `react-markdown` and `remark-gfm` (`components/reply-markdown.tsx`), loaded as a chunk of its own: a reply shows as plain text in its bubble until it has arrived. Headings, bold, italic, strikethrough, inline code, code blocks, nested lists, block quotes, rules and tables are drawn from the design tokens in both themes; a table keeps its header cells and, like a code block, scrolls sideways inside the bubble, reachable from the keyboard, never the page. A link with the scheme `http`, `https` or `mailto` opens in a new tab with `rel="noopener noreferrer"` and any other is text; an image is its alt text and is never fetched; raw HTML is text. A mark not yet closed while it streams shows as typed. The phone reads the same Markdown ([ADR 0225](adr/0225-draw-malangi-s-reply-as-markdown-with-gfm-in-a-bubble-through-the-dart-markdown-package-and-our-own-widgets.md)). A `choice` draws its prompt and its options as buttons on the last reply; a pick is sent as the next message.
- A proposal draws its note ("새 노트 · name" for a new one) and its groups on one surface: each group its check over its cards, its title, its form's chip (글, 단어, 빈칸 문장, 표, 사진, 섞어서), "다른 형식으로", which offers the other forms and sends "title 부분은 form 형식으로 다시 만들어 줘", and its cards, each a check over its first-shown text and what it adds; a group of six or more starts collapsed to "카드 n장 · form". A proposal sent again under its id keeps the checks of the groups it kept.
- A proposal's card is two lines (`card-preview.ts`): its first shown parts joined over what each adds. A 글's parts and a cloze of version 2, whose block holds `text` in Anki's syntax and no `answers`, are read by the engine through `@/design/markup-engine` ([ADR 0209](adr/0209-draw-and-edit-card-text-markup-and-anki-cloze-on-the-web-through-the-engine-s-document-read-where-a-card-is-read.md)): marks left out, each cloze `___`, its hint after it as `___(hint)`, and the answers as the second line, so a proposal never shows `{{c1::` or a mark's asterisks. The lines are drawn once the module has loaded (`useMarkupReady`), "—" until then.
- At the foot, the last proposal not yet added offers "n장 추가", or "n장 바꾸기" for changes, the cards checked. Once added, its checks go and a shortcut to the note, its name and "카드 n장", opens it; where the commit left cards out, "n장은 이미 노트에 있어요" and "n장은 추가하지 못했어요" follow the count, each only when above 0.

### Photos

- The field's "사진 첨부" takes JPEG, PNG or WebP, up to 50 a message. Each is prepared by `downscalePhoto` (`web/src/design/prepare-photo.ts`, photo import's own: upright, 2048 px on its long side, a JPEG under 3 MiB), staged above the field as thumbnails with "사진 삭제" under "사진 n장", and a file the browser cannot decode says "사진을 가져오지 못했어요. 다시 시도해 주세요." The send button is on for words or photos.
- A message with photos first says "사진을 올리는 중이에요" and uploads each, with the Supabase browser client as the user, to `assistant-photos` at `{user id}/{uuid}`; only when every one is stored does the message go, the ids in `photos`. One that fails sends nothing and says "사진을 올리지 못했어요. 다시 시도해 주세요.", the words and photos kept. The user's turn shows "사진 n장".
- The `job` event is kept on the reply and drawn as "n/m장 읽는 중", the photos not queued over those attached, over a bar, with "읽기 취소". The chat asks `GET /api/assistant/jobs/{id}`, a Route Handler that verifies the user and passes the function's status and body on, every 3 s while a job reads, and the Server Action `cancelPhotoJob` calls the function's cancel; a job the function no longer has, or whose cancel it accepted, reads "사진 읽기를 취소했어요", and one done "사진 n장을 다 읽었어요".
- Done while no message has followed the reply, the chat sends "사진 읽기가 끝났어요. 이어서 해 주세요." as the user's next turn, undrawn; done while a message is under way, the answer waits for the next ask. A stored running job is asked after again when the chat opens.

### Requests

- A message is `POST /api/assistant`, a Route Handler, since its answer is a stream (stack-nextjs §3): it verifies the session, forwards the body with the user's token to the function and passes its status and stream back as they arrive; the browser going away aborts the call. A visitor not signed in is answered `401` without calling.
- The commit is the Server Action `commitProposal`, which reads the proposal and the checks, sends them to `/assistant/commit` as the user, answers the note, the cards written and the counts of `skipped` and `refused` (0 where the answer has none), and revalidates the pages; a refused commit says "카드를 추가하지 못했어요. 말랑이에게 다시 만들어 달라고 해 주세요.".
- The upload, the poll and the cancel sit behind the same seam. `/api/assistant/jobs/[id]` refuses a visitor not signed in and an id that is no uuid without calling the function, and `cancelPhotoJob` reads its id before it sends it.
- Both sit behind `AssistantClient`, the seam the tests fill with a fake. The events are read at the boundary: an event of a name the chat does not draw is passed over, and a known one that is not its form ends the reply as failed.

### States

- `busy`: sent again after 3 s, up to three times, saying "앞의 메시지를 마무리하고 있어요. 잠시 후 다시 보낼게요.".
- `rate_limited`: "오늘 말랑이와 이야기할 수 있는 만큼 다 썼어요. 내일 다시 이야기해요.", the field removed and the share at its figure.
- A failed reply, `model_error`, says so with "다시 시도", which sends the message again in its place; a cut one says to ask for the rest; a turn whose `usage` event says `outcome` is `depth_limit` or `time_limit`, with no reply, proposal, question or photo job and no ending, ends as `limit` and says "할 일이 많아 여기서 멈췄어요. 다시 시도해 주세요." with "다시 시도" as a failed one does, while one with a reply shows the reply alone; "멈추기" stops a streaming reply, marked "멈췄어요.".
- A refusal before the start says what happened in one sentence, with "다시 시도" where sending again can help and "로그인" when the session ended.

### Entry

- 홈's mascot is the chat's one entry, a link to `/assistant` named "말랑이와 대화하기"; no other page draws 말랑이 as an entry, and the chat is opened from no note ([ADR 0248](adr/0248-meet-malangi-on-home-alone-offer-the-chat-once-a-day-in-a-bubble-over-the-mascot-and-open-it-naming-no-note.md)). The 노트 page, a note and 기록 draw no character at their edge.
- Over the mascot's head, in the link, one bubble at a time, both in `components/ready-bubble.tsx`: while the last proposal shown is not added, `ReadyBubble` says "카드 n장 만들어 뒀어요", read after the link's name (#742); otherwise `ChatBubble` offers the chat, by 홈's state: "오늘 배운 거, 같이 카드로 만들까요?" while cards are left today (the backlog included), "오늘도 수고 많았어요!" once the day's cards are done ([ADR 0249](adr/0249-say-only-praise-in-home-s-chat-bubble-once-the-day-s-cards-are-done.md)), and "말랑이와 대화해요" in any other state (no note, no card, a failed read).
- `ChatBubble` shows at most once a local day in this browser: the local date `YYYY-MM-DD` is kept in `localStorage` as `knowno.assistant.offer`, written when the bubble shows, so a 홈 left before it showed spends nothing; storage that refuses shows it each time. It shows 1.5 s after 홈 appears, stays 6 s and fades out over 300 ms, with no fade under `prefers-reduced-motion`, and never while the ready bubble shows or is ready. It is `aria-hidden`: the mascot's link already says it opens the chat. Its words are the phone's ([`assistant-app.md`](assistant-app.md)).
- The first run's one action is "말랑이와 첫 노트 만들기", a link to `/assistant` ([`web-study.md`](web-study.md)).

### Tests
