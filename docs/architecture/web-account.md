# Web account

The web's `account` feature: the sign-in page with Google's, Apple's and the email code's ways in, the code exchange, the account page and sign-out, and the consent page an AI app opens beside them. The session and the proxy every route reads are [`web.md`](web.md)'s; the app's `account` domain is [`account.md`](account.md).

## Current decisions

### Sign-in

- `/login` follows the phone's sign-in screen and the SignIn artboard: the stacked lockup, 알아몰라 alone and 150 wide, as the heading and the phone's welcome sentence on the ground's panel, rounded at the foot, then on the surface Google's button, "Google로 로그인", Apple's under it, and the consent line with the legal links. The button calls the browser client's `signInWithOAuth` for Google, with `redirectTo` the page's origin plus `/auth/callback`; while it starts, progress takes the mark's place and the button cannot be pressed again, and a failure to start is shown beneath it.
- Email sign-in on both sign-in pages is by a 6-digit code (`signInWithOtp`, then `verifyOtp` of type `email`), as the phone's; it is not built yet (#795), and the code's email, expiry and limits are [`server.md`](server.md) §Auth settings' ([ADR 0213](adr/0213-sign-in-by-email-with-a-six-digit-code-sent-in-korean-and-set-the-production-project-s-auth-by-hand-since-its-config-toml-section-is-not-applied.md)).
- The button is Google's, drawn to its branding guidelines (developers.google.com/identity/branding-guidelines, last updated 2026-07-07, re-read 2026-10-16 and 2026-11-04) as the phone draws it ([ADR 0024](adr/0024-one-voice-and-a-sheet-action-rule.md), [ADR 0031](adr/0031-keep-the-web-theme-choice-in-the-browser-draw-google-sign-in-at-the-app-height-and-hold-each-page-with-a-skeleton.md)): the light button in the light theme and the dark one in the dark, with `GoogleButtonStyle`'s fill, 1 px stroke and label colours and its 14/20 medium label as `@theme` tokens (`google-*`), the label in Google Sans ([`design/theme.md`](design/theme.md)), the guidelines' Android and web spacing, 12 px, 10 px and 12 px, its mark and label centred, and 48 high, `--spacing-google-height`, with the app's 24 px button radius, a capsule at that height ([ADR 0194](adr/0194-draw-google-s-and-apple-s-sign-in-buttons-48-tall-with-their-content-centred-and-keep-one-apple-nonce-until-a-sign-in-spends-it.md)); the guidelines name no height and let the button scale. It is as wide as Apple's button under it: the column's width up to `--container-sign-in`, 375 px, the widest Apple's script draws, centred ([ADR 0191](adr/0191-sign-in-with-apple-on-the-web-through-apple-s-js-button-in-a-popup-and-supabase-on-both-hosts-login.md)). Its "G" mark is `web/public/google/g-mark-light.png` and `g-mark-dark.png`, byte for byte the app's `app/assets/google/4.0x/` PNGs from Google's bundle ([`design/theme.md`](design/theme.md)), drawn at 20 px.
- Apple's button is Apple's, drawn by Sign in with Apple JS, which the feature loads from Apple's CDN through `next/script` on the two sign-in pages alone, in Korean, "Apple로 로그인" ([ADR 0191](adr/0191-sign-in-with-apple-on-the-web-through-apple-s-js-button-in-a-popup-and-supabase-on-both-hosts-login.md)): black in the light theme and white in the dark, with no border, drawn again when the theme changes, in `center-align`; as tall as Google's, 48, at which its title is 43% of the height, about 20.6 px beside Google's 14 px label, and its radius Apple's percentage of the height at 50, a capsule as Google's is ([ADR 0194](adr/0194-draw-google-s-and-apple-s-sign-in-buttons-48-tall-with-their-content-centred-and-keep-one-apple-nonce-until-a-sign-in-spends-it.md)); as wide as Google's, the column's width up to `--container-sign-in`, 375 px, centred, 12 under Google's. The repository holds none of Apple's artwork. A script that cannot load leaves no button.
- Apple's button opens Apple's popup through `AppleID.auth.init` with the Services ID `app.knowno.web`, the scope `name email`, the host's `/login` as its return URL, and the SHA-256 as hex of a raw nonce. The page keeps that nonce pair through a cancelled, closed or replaced popup, a theme change and a re-render, since Apple's script builds a popup from the nonce it was last given and reports an open popup closed after a press has built its replacement; a success event spends it, and the next sign-in draws a new one ([ADR 0194](adr/0194-draw-google-s-and-apple-s-sign-in-buttons-48-tall-with-their-content-centred-and-keep-one-apple-nonce-until-a-sign-in-spends-it.md)). On success the identity token and the raw nonce go to the browser client's `signInWithIdToken` for Apple, and the name Apple shares on a first sign-in is stored as on the phone ([`account.md`](account.md)), a failure there logged with the user signed in; the browser then opens `/`. While Supabase signs in, the button cannot be pressed again. A popup closed, cancelled or replaced is quiet; any other failure opens `/login?error=failed`, and Supabase's `user_banned` `/login?error=suspended`.
- **"이메일로 계속하기"** ([ADR 0215](adr/0215-sign-in-on-the-web-with-an-email-code-through-two-server-actions-as-a-third-way-beside-google-and-apple.md)), the third way, after Apple's: a secondary button of the buttons' width that opens, in its place, the email step: "이메일" (`type="email"`, `autocomplete="email"`) under the line "이메일 주소로 6자리 코드를 보내 드려요. 처음이라면 계정이 만들어져요." and "코드 받기", which sends a 6-digit code through the Server Action `sendEmailCode`; then the code step: "6자리 코드", `autocomplete="one-time-code"` and `inputmode="numeric"`, taking a pasted code with its spaces or hyphens, "로그인", which calls `verifyEmailCode` and opens `/`, the line "{seconds}초 뒤에 코드를 다시 받을 수 있어요" while it counts down 60 s from each send and then "코드 다시 받기", and "이메일 주소 바꾸기", back to the email step with the address kept. Both actions use `@supabase/ssr`, so the session is cookies on the host that asked; each parses its input first (`email-sign-in.ts`), and a failure comes back as its sentence under the field: rate limited with the seconds Auth names, counted down, a refused address, and a wrong or expired code (one sentence, since Auth answers both with `otp_expired`), each the phone's word for word ([ADR 0214](adr/0214-sign-in-with-an-email-code-on-the-phone-in-a-screen-opened-over-the-sign-in-screen-with-three-failures-added-to-the-account-failures.md)); and the web's own for offline, unavailable, a code of the wrong shape and a suspended account. The admin host's sign-in does not offer it; an email account reaches the admin area only as an admin does.
- `/auth/callback` is a Route Handler. It exchanges the code for the session cookie and opens `/`, or opens `/login?error=cancelled` when no code arrives, `/login?error=suspended` when Supabase Auth answers `user_banned` for a suspended account ([ADR 0072](adr/0072-suspend-a-user-through-supabase-auth-s-ban-and-restrictive-write-policies-remove-a-public-deck-from-sharing-for-good-and-read-any-deck-in-the-admin-area.md)), and `/login?error=failed` when the exchange fails otherwise; `/login` shows the matching sentence.
- Each origin the app is served from must be in Supabase Auth's allowed redirect URLs as `<origin>/auth/callback`, `https://admin.knowno.app/auth/callback` among them. Only the owner changes that list. Likewise the Services ID `app.knowno.web` must name `knowno.app` and `admin.knowno.app` among its domains and `https://knowno.app/login` and `https://admin.knowno.app/login` among its return URLs; a preview's origin and `localhost` are not there, so Apple's popup refuses on them.
- The admin host has a sign-in of its own at its `/login`, drawn from this feature's Google and Apple buttons and `CallbackError`, the sentence for each error above; sign-out there is this feature's `signOut`, which opens that host's `/login` ([`web-admin.md`](web-admin.md), [ADR 0178](adr/0178-serve-the-admin-area-at-admin-knowno-app-from-the-same-web-app-routed-by-host-in-its-own-shell-and-session.md)).

### Account page and sign-out

- `/account` reads the session on the server and shows the account's email, the daily study minutes with what they mean for today's new cards, read over every deck as 홈 reads its day, or why they could not be read, "로그아웃" and "계정 삭제", or that the server cannot be reached with "다시 시도", which reads the page again, above "화면", which needs no server (#276); the menu's 설정 opens it. Signed in, it first reads `my_plan()` ([`server.md`](server.md) §Store plans) for "내 플랜" and for AI 연결's lock; while that read fails, no 내 플랜 is drawn and nothing is locked or offered.
- `/account` is drawn as the phone's settings screen, 설정 ([ADR 0118](adr/0118-name-each-concept-once-write-each-role-in-one-form-hold-every-screen-to-one-set-of-visual-details-and-redraw-settings-and-the-deck-screen-by-them.md), #446): "설정", then four muted section labels over one group each, its rows parted by hairlines and each its words alone ([ADR 0116](adr/0116-draw-an-icon-only-where-it-says-what-the-words-beside-it-do-not-or-follows-the-platform.md)): "내 플랜", the app's card read-only, matching the app's card: the plan, 무료, 플러스 or 프로 (스페셜 is read as 프로, as `my_plan()` answers it), "사진 n/m장 사용", or "제한 없이 쓸 수 있어요" where nothing limits it, and a store plan's "다음 갱신 <date>" or, once it does not renew, "<date>까지 쓸 수 있어요", the date in the browser's zone; under the group, on 무료 "플러스는 knowno 앱의 내 플랜에서 시작할 수 있어요.", and on a store plan "구독은 구매한 곳에서 관리해요. 지금은 App Store예요."; the web sells nothing, so there is no purchase button, link or price, and an admin, a 무제한 holder and a plan an admin gave are told nothing to buy; "계정", the email, "로그아웃", then "계정 삭제" in red; "학습", "하루 학습 시간" with the minutes and a chevron, read as "하루 학습 시간 n분", which opens `study`'s dialog that changes them, the one place they change on the web ([ADR 0091](adr/0091-draw-the-today-card-as-a-progress-bar-and-change-the-daily-study-minutes-only-in-settings.md), [`web-study.md`](web-study.md)); and "AI 연결", the MCP server's address and how to add it in Claude and in ChatGPT, which needs no server and is drawn while the server cannot be reached too ([`mcp.md`](mcp.md) §Settings entry); on 무료, which `mcp.md` §Plan gate refuses, it shows only "AI 연결은 플러스부터 쓸 수 있어요. 지금은 무료 플랜이라 연결할 수 없어요. 플러스는 knowno 앱의 내 플랜에서 시작할 수 있어요.", with no address; a paid user, an admin and a 무제한 holder see it as before; and "화면" with the theme choice, three rows, the chosen one ending in a check; then the legal links at its foot. No avatar and no mascot.
- `/oauth/consent` is the consent page Supabase Auth's OAuth server opens for an AI app connecting to the account, outside the shell as `/login` is; what it shows and how it answers are [`mcp.md`](mcp.md) §Consent page; for a 무료 user it shows the same sentence, offers only "취소" and cannot grant, since `my_plan()` is read on the server and "연결" is not drawn ([ADR 0126](adr/0126-connect-claude-and-chatgpt-through-one-remote-mcp-server-acting-as-the-signed-in-user.md)).
- `my_plan()` is read by the `account` feature's `readMyPlan`, and `mcpLocked` is true for a `free` plan whose source is `none`, which is what the server refuses; an `admin` or `unlimited` source is never locked. A store plan is bought in the app, so the web never offers it.
- "계정 삭제" is the group's last row, drawn as the app's, and asks first through `Confirm` ([ADR 0247](adr/0247-delete-the-account-from-the-web-s-account-page-through-delete-account-send-no-apple-code-and-publish-the-way-at-privacy-delete-account.md)): "계정을 삭제할까요?", the app's sentence without "this device", "취소" and, last, a red "삭제"; while `my_plan()` answers `source: store` it adds that deleting does not cancel the store subscription, with no button, since the web cannot open the store's management, and an unknown plan or any other source leaves it unchanged, the deletion never blocked. "삭제" is the Server Action `deleteAccount`, which re-verifies the session, posts to the `delete-account` Edge Function with the session's access token and no body, and on success ends this browser's session and opens `/login?deleted=1`, where `/login` says the account was deleted; any other answer, or none, keeps the session and the dialog shows a sentence, "삭제 중" and disabled while it runs. The web sends no Apple authorization code, so a web deletion does not revoke Sign in with Apple ([`account.md`](account.md) §Deletion).
- Sign-out is the Server Action `signOut`, through the `account` feature's `actions.ts`; while it runs, the row shows progress at its end and cannot be pressed again. It revokes this browser's session alone (`scope: "local"`), so the phone stays signed in, and opens `/login`. When Supabase cannot be reached it returns the sentence the form shows.
