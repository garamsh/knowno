# Server AI

The server's side of photo extraction: the extraction count, the AI providers and configurations each plan is served by with their keys in Vault, and the prompt store with the record of each counted photo.

## Current decisions

### Extraction usage

- `public.extraction_usage` holds one row per photo extraction the `extract-cards` function let through: an identity `id`, `user_id` referencing `auth.users` with `on delete cascade`, and `created_at` ([`ai-extraction.md`](ai-extraction.md), [ADR 0013](adr/0013-extract-cards-function-and-eval.md)).
- It is not synced: it has no revision, tombstone or edit time.
- `authenticated` may only select it, and row-level security allows only the caller's rows, so the app can read today's count. `anon` holds nothing.
- Rows are written only by `public.begin_extraction(user_id)`, which the function calls (§Prompt store), executable only by `service_role`. It takes a transaction-level advisory lock on the user, counts the rows since the start of the period of the user's plan version ([`server-plans.md`](server-plans.md) §Plans), and inserts one under its limit, or whatever the count for a user on 스페셜 ([`server-plans.md`](server-plans.md) §Plans, "스페셜"). `service_role` itself may not insert directly. Migration `20261019230001_drop_old_function_entry_points.sql` dropped `public.consume_extraction` and `public.start_extraction`, which only a function deployed before plans or the prompt store called, changing no row ([ADR 0078](adr/0078-keep-no-older-app-or-function-build-working-until-the-first-store-release.md)).
- The lock's key is the hash of the user id seeded with 1, never the revision lock's seed 0.
- `public.extraction_allowance()`, `security definer` and executable only by `authenticated`, returns the caller's `photo_limit`, null for a caller on 스페셜 ([`server-plans.md`](server-plans.md) §Plans, "스페셜"), and naming no plan, its `period` (`month` or `day`) and `used`, the caller's rows since the period's start, read from `auth.uid()` with no user argument, so the app can say before reading several photos how many the period leaves ([`ai-extraction.md`](ai-extraction.md), [ADR 0089](adr/0089-import-up-to-ten-photos-into-one-list-read-two-at-a-time-and-state-today-s-limit-before-reading.md), [ADR 0097](adr/0097-give-each-plan-versions-of-its-terms-with-a-start-free-10-a-month-pro-100-a-day-and-max-unlimited-to-1000-a-day-each-grant-taking-the-latest-at-its-monthly-renewal.md)). It resolves the version through `private.entitlement_of` and counts the same rows from the same start as `begin_extraction`, so the two agree; it takes no lock and writes nothing. Migration `20261019234136_extraction_allowance.sql` added it, changing nothing that existed, and `20261026005136_plan_versions.sql` replaced it with these columns.
- The migration adding it is additive: it creates the table, its index and the function, and changes nothing that existed.

### AI providers

- Each plan, 스페셜 included, is served by an AI configuration, a provider, `openrouter`, `openai` or `anthropic`, its model and a prompt version (§Prompt store) ([ADR 0182](adr/0182-make-each-plan-s-ai-configuration-its-provider-model-and-prompt-version-with-one-draft-tried-and-applied-as-a-unit-in-one-admin-ai-section.md), [ADR 0162](adr/0162-choose-each-plan-s-ai-provider-in-admin-keep-provider-keys-in-vault-and-apply-a-configuration-only-after-a-check-call-and-an-admin-s-trial.md), [`ai-extraction.md`](ai-extraction.md) §Switching the model).
  - `private.ai_configurations` holds them append-only; a trigger refuses every change but its author's removal. A model is checked to its provider's form by `private.model_fits`: OpenRouter's `vendor/model`, the others' bare id.
  - `private.ai_configurations.prompt_version_id` names the version a configuration sends; it is null only on a configuration saved before ADR 0182, which no label names.
  - `private.ai_configuration_labels` names each plan's `active` configuration, served to its users, and its one draft, `test`, served to admins, tried, applied and ended as a unit. A row exists only after `extract-cards`' check call on it parsed.
  - `private.extraction_calls.provider` records the provider that served each counted photo.
- `begin_extraction` serves an admin who names a configuration some label holds that configuration (the trial and its comparison), an admin otherwise its plan's draft while one is set, 스페셜's since every admin is on it ([`server-plans.md`](server-plans.md) §Plans), and everyone else the active one, each with the provider, model and prompt version the configuration holds. A configuration named by a user who is not an admin, or one with no prompt version, returns no row. It answers `available`: whether the provider has a key in Vault, OpenRouter as every other. Only an available photo is counted.
- **Keys** are Vault secrets named `knowno_provider_key_<provider>`, one per provider. `private.provider_keys` holds each one's Vault id, its last four characters, and who set it and when.
  - A key is found only through its `provider_keys` row, which `save_provider_key` writes after the function's check call parsed: a secret added to Vault directly, by any name, is never read, and its provider stays unavailable.
  - `public.provider_key(provider)` is the one function that returns a key decrypted, executable by `service_role` alone.
  - `public.save_provider_key(admin_id, provider, key)` creates or updates the secret and records `set_provider_key` with the provider alone. It is `service_role` only, called by the function after the check call parsed, and refuses an `admin_id` that is no admin.
  - `public.save_ai_configuration(admin_id, plan, provider, model, prompt_version_id)` appends a configuration as the plan's draft, replacing any draft, and records `save_ai_configuration` with the version, under the same rules. Without a version it keeps the draft's, or else the active one's; a version that does not exist answers null, recording nothing.
- The admin functions, each checking the role and recording itself as [`server-admin.md`](server-admin.md) §Admin area states:
  - `admin_ai_session`, whether the caller signed in within 10 minutes, by the JWT's `amr` times;
  - `admin_provider_keys`, each provider's last four characters, who set it and when, and whether an active configuration uses it, never the key;
  - `admin_ai_configurations`, each plan's labelled configurations with their prompt versions;
  - `admin_activate_ai_configuration(plan)`, 모두에게 적용, making the draft's provider, model and version active together, under an advisory lock seeded with 6, refused while the draft's provider has no key;
  - `admin_clear_ai_test(plan)`;
  - `admin_remove_provider_key(provider)`, which needs a recent sign-in and refuses a key an active configuration uses;
  - `admin_configuration_results(days)`, over the last 1 to 90 UTC days, 30 by default, one row per provider, model and prompt version that served a recorded photo, whichever plan, with the outcome counts and failure rate `admin_extraction_failures` reads.
- No audit row holds a key or its last four characters (`ai_providers_test.sql`).
- **Cost.** Vault is a table in the database, available on every project, which Supabase does not bill apart: a key costs its row's size ([ADR 0162](adr/0162-choose-each-plan-s-ai-provider-in-admin-keep-provider-keys-in-vault-and-apply-a-configuration-only-after-a-check-call-and-an-admin-s-trial.md) cites the docs).
- Migration `20261102183518_ai_providers.sql` is not additive, so it merges with the owner's approval:
  - it copies every version's model into `private.plan_versions_models_before_ai`;
  - it seeds each plan's active configuration on OpenRouter with its current version's model;
  - it records every earlier call as OpenRouter's;
  - it drops `plan_versions.model`, `private.migrate_plan_versions` and the model from `in_favour`, `entitlement_of`, `admin_plan_versions`, `admin_create_plan_version` and `revert_plan_versions`;
  - it replaces `begin_extraction` and `resume_extraction` with the provider added.
  - Its header states the revert.
- Migration `20261103133627_remove_openrouter_transition.sql` ends the OpenRouter transition of [ADR 0162](adr/0162-choose-each-plan-s-ai-provider-in-admin-keep-provider-keys-in-vault-and-apply-a-configuration-only-after-a-check-call-and-an-admin-s-trial.md), changing no row: it creates `begin_extraction(uuid, bigint)` with the same grants, and replaces `admin_activate_ai_configuration` without OpenRouter's exception. Its header states the revert.
- Migration `20261104000000_drop_begin_extraction_wrapper.sql` drops `begin_extraction(uuid, bigint, text[])`, the wrapper kept while the old `extract-cards` bundle named `secret_providers` (#669). It changes no row. Its header states the revert.

### Prompt store

- `private.prompt_versions` holds every saved prompt: an identity `id`, the `text`, at least one non-space character and at most 20,000 characters, a `note` of at most 200, `created_by`, set null when that account is deleted, and `created_at` ([ADR 0073](adr/0073-keep-the-extraction-prompt-as-append-only-versions-in-the-database-served-by-an-active-and-an-admin-only-test-label-and-record-what-served-each-call.md)). A trigger refuses every update and delete but that author's removal, so versions are append-only. A version is the model's instructions only: the function sends its text unchanged and then its own fixed output contract, the fields and rules of a card, which no version holds or changes ([ADR 0124](adr/0124-send-a-fixed-output-contract-after-every-prompt-version-and-keep-a-reply-s-valid-cards.md), [`ai-extraction.md`](ai-extraction.md) §Model call).
- A version is served through the AI configuration that names it (§AI providers): a plan's active configuration's to its users, its draft's to admins ([ADR 0182](adr/0182-make-each-plan-s-ai-configuration-its-provider-model-and-prompt-version-with-one-draft-tried-and-applied-as-a-unit-in-one-admin-ai-section.md)). Saving a version serves it to no one. `private.prompt_labels`, ADR 0073's global `active` and `test`, is kept renamed as a backup ([`server-migrations.md`](server-migrations.md) §Configuration prompts migration).
- `private.extraction_calls` records what served each counted photo: its `extraction_usage` row, deleted with it, the plan, the model and the prompt version, with no image, card or prompt text.
  - It also records how the photo ended ([ADR 0130](adr/0130-retry-a-failed-photo-once-within-one-usage-and-record-each-extraction-s-outcome.md)): `outcome`, `ok`, `no_cards`, `invalid_output` or `model_error`; `attempts`, 1 or 2; `latency_ms`; `cards_returned` and `cards_dropped`, of the last reply; and `failures`, each failed call's kind in order, `invalid_output`, `model_error` or `timeout`. A check holds them all null or all set, with one failure per call, one fewer when the last call answered, and cards only on `ok`. Migration `20261101075233_extraction_truncated.sql` adds `truncated`, whether the last reply was cut at the output cap, null on rows recorded before it or by a function that does not send it, and `true` only on `ok` or `invalid_output` ([ADR 0135](adr/0135-keep-the-cards-a-reply-cut-at-the-output-cap-completed-say-the-photo-was-read-in-part-and-measure-three-ways-to-read-a-dense-page-whole.md)). Migration `20261101150000_extraction_continuation.sql` ([ADR 0138](adr/0138-read-a-photo-to-the-end-of-its-page-by-reading-a-cut-reply-on-in-the-request-and-going-on-with-a-cursor-the-photo-counted-once.md)) makes `truncated`, on a photo answered with cards, whether its page was left unread past them, makes `cards_returned` the photo's cards over its requests, up to 500, and adds `continuations`, the calls that read on after a cut reply, and `resumes`, the requests that went on with a cursor, each null on rows recorded before it. A row with no outcome was counted before migration `20261031181717_extraction_outcomes.sql`, or its request ended unexpectedly.
  - `public.finish_extraction(usage_id, outcome, attempts, latency_ms, cards_returned, cards_dropped, failures, truncated, continuations, cursor)`, executable only by `service_role`, records them on the call of the usage row `begin_extraction` named, once: a call already recorded or never begun raises `P0002`, parts in disagreement `23514`. A `cursor` given is kept in `private.extraction_cursors` with the usage row for 10 minutes, replacing any the photo had.
  - `public.resume_extraction(user_id, cursor)`, executable only by `service_role`, takes a cursor: it deletes it and returns the usage row, the plan, model, prompt version and its text of the photo's first read, and its cards and continuing calls so far; no row when the cursor is unknown, taken, expired or another user's ([ADR 0138](adr/0138-read-a-photo-to-the-end-of-its-page-by-reading-a-cut-reply-on-in-the-request-and-going-on-with-a-cursor-the-photo-counted-once.md)).
  - `public.record_resumed_extraction(usage_id, continuations, cards_returned, truncated, cursor)`, executable only by `service_role`, adds a request that went on with a cursor to a finished call: its calls and cards, one to `resumes`, `truncated` replaced, and the next cursor kept as `finish_extraction` keeps one; a call with no outcome raises `P0002`, more than 500 cards `23514`.
- `public.begin_extraction(user_id)`, executable only by `service_role`, resolves the plan and the configuration serving the user, with its prompt, and, under the plan's limit, records the photo and its call, under the extraction lock (§Extraction usage), returning the usage row as `usage_id`, null when the photo is refused. It returns no row while the plan's settings or its configuration's version are missing. `public.prompt_version(version_id)`, also `service_role` only, gives the eval a version's text.
- The admin functions, each checking the role and recording itself as [`server-admin.md`](server-admin.md) §Admin area states: `admin_prompt_versions` and `admin_prompt_version`, each version's labels being `active` while some plan's active configuration sends it and `test` while some plan's draft does; and `admin_save_prompt` (`save_prompt` on a `prompt`, with the note and the length). `admin_set_prompt_label` and `admin_clear_test_prompt` went with the labels.
- `admin_extraction_breakdown(days)`, checking the role, returns each UTC day's photos over the last 1 to 90 days by the plan, model and version of their call record, a photo without one under none; 처리할 일 reads 14 for its two weeks ([ADR 0074](adr/0074-chart-the-overview-s-photos-and-cost-by-day-plan-model-and-prompt-version-with-recharts-each-chart-an-image-named-by-a-sentence-beside-a-table.md)). Migration `20261019220000_extraction_breakdown.sql` adds only it.
- The outcome reads #509's admin page uses, each checking the role ([ADR 0130](adr/0130-retry-a-failed-photo-once-within-one-usage-and-record-each-extraction-s-outcome.md)):
  - `admin_extraction_calls(before, page_size)` — the call records newest first, a page of 1 to 500, 100 by default, before the usage id `before`: `usage_id`, `created_at`, `user_id`, `plan`, `model`, `prompt_version_id` and the outcome's six columns;
  - `admin_extraction_failures(days)` — over the last 1 to 90 UTC days, 30 by default, one row per day and prompt version: `calls` with an outcome, `ok`, `no_cards`, `invalid_output`, `model_error`, `retried` (2 calls), `recovered` (retried into `ok` or `no_cards`), `failure_rate`, the share of `calls` that failed to four places, null with none, and `unrecorded`, the calls with no outcome.
- Migration `20261031181717_extraction_outcomes.sql` is additive: it adds the six nullable columns and their check, every existing row keeping null, replaces `begin_extraction` with its body unchanged and `usage_id` returned, and adds the three functions. It changes no row.
- Migration `20261019210000_prompts.sql` creates the three tables, their indexes, the trigger and the functions, and seeds version 1, prompt v8, as active; it changes no existing row and replaces no existing object.
- Migration `20261019230003_activate_prompt_v9.sql` activates prompt v9 as `admin_set_prompt_label` would, by the owner's delegation to the PM, who cannot sign in to the admin area (ADR 0080):
  - it saves `prompt_v9.ts`'s text as version 2 with the note "prompt v9 (#261, #266), PM eval 2026-10-19: dense 89.3/90.5";
  - it points the `active` label at version 2 under the labels lock;
  - it records `activate_prompt` on `prompt` `2`, with the version before and no test label cleared, as `migration (owner delegated to PM, 2026-10-19)` with no admin id.
  - It changes no version: activating version 1 in the admin area serves prompt v8 again.

## Rationale

- [ADR 0013](adr/0013-extract-cards-function-and-eval.md) records why the extraction count is a table written through one locked function.
- [ADR 0162](adr/0162-choose-each-plan-s-ai-provider-in-admin-keep-provider-keys-in-vault-and-apply-a-configuration-only-after-a-check-call-and-an-admin-s-trial.md) records why each plan's provider and model are an AI configuration saved after a check call, tried by admins and applied to everyone, why provider keys live in Vault and are saved through the function, the OpenRouter transition and its end, the cost of Vault, and the lossless removal of the version's model; issue #598 records the owner's decisions.
- [ADR 0182](adr/0182-make-each-plan-s-ai-configuration-its-provider-model-and-prompt-version-with-one-draft-tried-and-applied-as-a-unit-in-one-admin-ai-section.md) records why a configuration holds its prompt version, why a plan has one draft, and why the move appends configurations, backs up both label tables and keeps the earlier extract-cards bundle working; issue #650 records the owner's direction and the PM's decision.
- [ADR 0073](adr/0073-keep-the-extraction-prompt-as-append-only-versions-in-the-database-served-by-an-active-and-an-admin-only-test-label-and-record-what-served-each-call.md) records why the prompt is append-only versions with an active and an admin-only test label in one global setting, why the contract stays in the function, and why each call records its plan, model and version.
- [ADR 0130](adr/0130-retry-a-failed-photo-once-within-one-usage-and-record-each-extraction-s-outcome.md) records why each counted photo's outcome is columns of its call record, written once through `finish_extraction` by the usage row `begin_extraction` names, and read by two admin functions.
- [ADR 0138](adr/0138-read-a-photo-to-the-end-of-its-page-by-reading-a-cut-reply-on-in-the-request-and-going-on-with-a-cursor-the-photo-counted-once.md) records why a photo's cursor is a stored token taken once, for its own user, within 10 minutes, and why a request with a cursor adds to the photo's record rather than counting a photo.
