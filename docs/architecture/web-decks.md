# Web decks

The web's `decks` feature: the deck list, a deck's page, the first run with no deck, the card content blocks and how a side is drawn. The pages' shell and the server reads they share are [`web.md`](web.md)'s; the app's `deck` domain is [`deck.md`](deck.md).

## Current decisions

### Reads

- The 노트 page (`/decks`) reads `decks`' `readDeckList` and `study`'s `readToday` together, as 홈 does ([`web-study.md`](web-study.md)); `/decks/[id]` reads `readLibrary` over the deck it names (that deck with its description, and its cards with both sides), `readToday` and the user's display name (`readDisplayName`), together; its title reads the same `readLibrary` through React's `cache` (`read-deck.ts` beside the page), so the page and its title make one request (#281).
