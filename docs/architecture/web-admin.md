# Web admin

The web's `admin` feature: the admin area at `admin.knowno.app`, its host, sign-in, shell, gate, sections, actions and reads. The role, the audit log and the functions behind it are [`server.md`](server.md)'s.

## Current decisions

### Area

- Operators run the service from its own host, `admin.knowno.app`, on the web only; the app has no admin screen ([ADR 0070](adr/0070-run-the-service-from-a-web-admin-area-whose-role-and-audit-log-live-in-the-database-and-whose-every-read-and-write-is-checked-there.md), [ADR 0178](adr/0178-serve-the-admin-area-at-admin-knowno-app-from-the-same-web-app-routed-by-host-in-its-own-shell-and-session.md)). The same web app serves it: the proxy rewrites each path of the admin host into `web/src/app/admin/` and moves the service's `/admin/*` there ([`web.md`](web.md) §Session and proxy), so every address in this document is a path on the admin host, `/users` being `admin.knowno.app/users`, served by the route `/admin/users`. The area's links, redirects and history entries name these paths; its Server Actions' `revalidatePath("/admin", "layout")` names the route, as Next.js asks behind a rewrite.
- **Sign-in.** The admin host signs in on its own, since the session's cookies stay on the host that set them: a signed-out visitor goes to its `/login` (`web/src/app/admin/login/page.tsx`), "관리자 로그인" under the brand over "관리", with the sentence "관리자 계정으로 로그인해 주세요. 서비스의 로그인과는 따로예요.", Google's button and the reason a sign-in failed, as the service's `/login` draws them ([`web-account.md`](web-account.md)), and no link into the service. The code exchange is the service's `/auth/callback`, on the admin host, which opens its `/`.
- **The gate.** The area's layout, `web/src/app/admin/(area)/layout.tsx`, renders nothing until the server's `is_admin` answers, inside a Suspense boundary with an empty fallback: an admin then sees the shell and the page; a signed-in account that is not an admin gets one line, "관리자만 들어올 수 있어요.", under the brand, with "다른 계정으로 로그인", which signs it out of the admin host and opens its sign-in, and nothing of the area; a server that cannot answer gets the error page. The area's pages set no metadata but the sign-in's, "관리자 로그인 · 알아몰라".
- **The shell** (`admin-shell.tsx`) has none of the service's menus. From 1024 px a side menu 240 px wide on the surface, pinned as the page scrolls, holds the brand, the lockup over "관리", which opens 처리할 일, the section menu, and at its foot, above a hairline, the admin's email, "서비스 열기" beside Lucide's external-link icon, hidden from assistive technology (the arrow character is in neither Jua nor Pretendard ExtraBold), which opens the service's address, handed to the page by the proxy, in a new tab, and 로그아웃, which signs this host out alone and opens its sign-in. Below 1024 px a bar over the page holds the brand and "메뉴", which opens the same menu and foot as a full screen, "관리 메뉴" beside "닫기", through `useModalDialog`; a section's link there drops the screen's history entry, closes it and opens the section, and Escape and the browser's back close it. The page sits in one `main` up to 1040 px wide, reached by "본문으로 건너뛰기".
- The role and every check live in the database ([`server.md`](server.md) §Admin area): every read and write is one of the server's admin functions, called with the user's session and the publishable key, and each refuses a caller who is not an admin. The web holds no service-role key and no admin's email or id.
- Each section's page is headed by its name in the menu (#326).
- Every page follows [`design/copy.md`](design/copy.md) and [`design/principles.md`](design/principles.md), as the web's settings and deck pages do (#509): each list or set of facts is one group of hairline rows on the `group` radius under a muted section label, through `web/src/design/section.tsx`'s `Section` and `admin-section.tsx`'s `group`, `row`, `linkRow` (a row that opens a page), `button`, `field`, `formLine` and `formInput` (a form's line in a group and its field) and `filter` (a select over a list) classes and its `Facts` (a set of facts as term and value rows), its `button` each a role of `web/src/design/button.ts`; rows of the same columns an operator compares are one table, `design/frames.md` §Table, through `admin-table.tsx`'s `AdminTable`, its `rowClass`, `cellClass` and `CellLabel`, and its `Pager` ([ADR 0181](adr/0181-list-every-user-in-admin-as-a-paged-table-filtered-by-plan-and-status-with-the-one-chosen-beside-it-and-give-plans-and-admins-a-page-each.md)); the admin skeleton takes `group` and `row` from the same file; a state is the one chip (`web/src/design/chip.tsx`), 숨김, 신고 n, 정지됨 and 공유 삭제 in amber, 사용 중, 관리자 and the user's plan, 스페셜 among them, in the brand tint, the rest neutral, the menu's count of new reports included, and no state is red, which means 모른다, but a failure rate over 5%, drawn in `dont-know-text` ([ADR 0155](adr/0155-organise-the-admin-area-in-five-sections-by-the-job-to-do-and-show-only-what-an-operator-acts-on.md)); a card of 처리할 일 or 사진 AI and a view switch are solid surfaces on their edge, and a button in a card or a row is outlined, a tap target high, in the `label` type (`admin-section.tsx`'s `card` and `button.row`); a field inside a group has no border until it is focused, then a 1.5 px ink outline; a page has at most one primary (지정, 저장), the plans page none, since it draws a form per plan, and every other button is outlined; a removed line of the prompt diff is on the amber tint; the one action that cannot be undone, 공유에서 영구 삭제, opens from red text at the end of the deck's page and under a note row's ⋯; and the user's 이용 정지 is the user page's last section. The shell sets `word-break: keep-all` over every page, so Korean breaks only between words. A page draws its title, the body's 16 and the caption's 13, beside a card's figure; an empty list says what is true, then what to do; and a page that could not read says what failed and what to do, with "다시 시도" unless the reader is not an admin.
