# Sharing

The `sharing` domain: publishing a deck, and browsing, previewing, copying, reporting and blocking other users' public decks, and how admins moderate them.

## Current decisions

### Surface and location

- The domain lives in `app/lib/sharing/`; its public surface is `app/lib/sharing/sharing.dart`, with internals under `app/lib/sharing/src/` ([ADR 0002](adr/0002-domain-public-surface-and-shared-database.md)).
- The surface exports what the composition site constructs, what `home/` composes and what tests substitute:
  - `SharingService`, which browses, publishes and unpublishes, and its copy targets `CopyTarget`, `CopyIntoNewDeck` and `CopyIntoDeck`;
  - `sharingServiceProvider`, the service or null while the app has none, which hides every entry to sharing, and `onlineProvider`, whether the device is online as the service reports it, offline without one;
  - `SharingServer`, the seam to the server, and `SupabaseSharingServer`, its PostgREST implementation;
  - `Reachability`, the network state, and `DeviceReachability`, over `connectivity_plus`;
  - the model: `PublicDeckSummary`, `PublicCard`, `DisplayName`, `BrowseSort`, `ReportReason`, `ReportOutcome`;
  - the failures: `SharingFailure`, `SharingOffline`, `SharingRejected`, `SharingFailed`, `DeckNoLongerPublic`.
- It depends on `deck` (the repository, the model, `addCards`, `CardBackRow`, the 칸 frame's decoding) and `account` (`UserId`) through their surfaces. `deck` does not reach it: `home/`'s screens read `sharingServiceProvider`, which the composition site overrides with the service it constructs ([`home.md`](home.md), [ADR 0039](adr/0039-name-every-top-level-folder-by-its-responsibility-compose-across-domains-in-a-home-shell-and-keep-seams-off-screens.md)). It imports `supabase_flutter` for PostgREST, beside `account` and `sync` ([ADR 0020](adr/0020-public-decks-in-a-sharing-domain.md)).
- `main.dart` builds `SupabaseSharingServer` over `connectAccount`'s client; a build that cannot sign in has no client, so no sharing and no entries for it.

### Publishing

- The deck screen's deck menu offers "노트 공개" on a private deck and "비공개로 전환" on a public one. While `Reachability` reports no connection, the item is disabled with "인터넷에 연결되면 바꿀 수 있어요".
- "노트 공개" opens a sheet titled with the deck's name and "공개": the display name the first time (2 to 20 characters, trimmed), an optional description of at most 300 characters, and the required checkbox "부적절하거나 저작권을 침해하는 내용은 공개하지 않을게요", then "공개", disabled until it is checked.
- **No client writes `visibility = public`** ([ADR 0238](adr/0238-screen-a-note-by-rules-in-the-publish-note-function-keyed-by-a-hash-of-its-text-and-let-no-client-write-make-a-deck-public.md), [`server.md`](server.md) §Note screening, [`sync.md`](sync.md) §No client write makes a deck public). A publish asks the `publish-note` function, which records the request as the owner and screens the note at once, and answers `checking`, `held`, `refused` or `public` with the places a refusal was found; a note that is checking or held is not yet visible. An app that still writes the visibility itself is refused until it changes.
- A publish writes the server first, then the device: the profile when it is new, then the deck's row without a visibility, which the server creates private or leaves as it is, then `POST publish-note` with the deck's id and the description, then the local row through `DeckRepository.setVisibility`, unsynced, for sync to push as usual. `writeVisibility` answers a `Screening` (the state, the refusal's layer and the findings), and an answer of `checking`, `held`, `refused` or `public` is an answer, not a failure; an unknown state, or one that is not an object, is `SharingFailed`. `SharingService.makePublic` records it on the device as one `DeckVisibility` through `DeckRepository.setVisibility`: `public` is `PublicDeck`, `checking` is `CheckingDeck`, `held` is `HeldDeck` and `refused` is `RefusedDeck`, so a deck cannot be public and refused at once. The repository maps the variant to the `visibility` and `publication` columns in one exhaustive switch and back in another: a checking or held deck keeps `visibility = public` in its row, so a later private push is not read by the server as an unpublish that lifts the hold ([`sync.md`](sync.md) §No client write makes a deck public), and a refused one is private with `publication = refused`. A status of 401 or 403 is `SharingRejected`, 0 (no answer), 500, 502, 503 or 504 `SharingOffline`, any other `SharingFailed`.
- The sheet waits for the server's check with a sentence saying so, its fields and button disabled meanwhile. `checking` and `held` end in one sentence of why, with a close button. `refused` keeps the form and says why in one sentence; a finding is a row naming where it was found (the note's name, its description, a card's front or back), the passage when the block holds one string (the server's `my_deck_screening` leaves out a finding's `field`, so a 칸 with text on both sides, or a block that is not text, shows its category and place without the passage), and the category, in words; a row with a card opens that card for the owner to fix, and publishing again is the same sheet. The same sentence stands on the deck's screen and its chip reads the state (`publicationLabel`, `publicationWhy` in `deck_row.dart`, each an exhaustive switch over the variants).
- "비공개로 전환" writes `visibility = private` to the row, which the server allows, the same way and keeps the description for the next publish.
- A public deck shows a "공개" chip on its row on the home screen, and "· 공개" after "카드 n장" under its name on the deck screen ([`home.md`](home.md)).

### Browsing

- "공개 노트 둘러보기" opens the browse screen: the one item of the 노트 tab's ⋯ ([ADR 0172](adr/0172-make-a-note-with-the-choices-of-its-customization-head-the-notes-and-a-note-with-a-tonal-action-and-a-menu-over-an-always-shown-search.md)), and the first-run home's quiet button ([`home.md`](home.md), [ADR 0067](adr/0067-start-a-deck-or-a-card-from-one-sheet-that-holds-the-photo-source-and-name-public-decks-once.md)).
- The screen has a large title, "공개 노트", a search over name and description (ignoring case, run 300 ms after typing pauses), and a segmented "최신순" / "가져오기 많은 순".
- Each row shows the deck's name and "{display name} · 카드 n장 · 가져오기 m회". The listing comes from `list_public_decks` ([`server.md`](server.md)), at most 100 decks; decks of users the user blocked are absent.
- Offline, the screen shows "인터넷에 연결되지 않았어요. 연결되면 공개 노트를 볼 수 있어요." and lists once the connection returns; a failed request shows its message with "다시 시도".

### Preview and copy

- A tap opens the preview: the name, the owner's display name with the counts, the description, and the first 20 cards in one group as the deck screen's rows draw a card, what study hides on the hatch, each framed card from its 칸 ([ADR 0137](adr/0137-frame-a-card-by-its-blocks-each-block-type-deciding-whether-it-has-a-front-and-a-back.md)), with "카드 n장 중 처음 20장" when there are more.
- "내 노트로 가져오기" opens a sheet: "새 노트로", the default, creates a deck named after the public one; "기존 노트에 추가" takes one of the user's decks and a duplicate option, "건너뛰기" by default, or "뒷면 합치기" or "새 카드로 추가".
- A copy reads every live card of the deck, calls `record_deck_copy`, which counts the user's first copy of the deck and no later one, and refuses with `DeckNoLongerPublic` when the deck is no longer public. It then saves through `DeckRepository.addCards` with `FromCopy`, so each added card is an ordinary card with `source = copy` and `origin_deck_id`, and the duplicate rule of [`deck.md`](deck.md) applies. A copy into a new deck adds every card, duplicates included. Nothing links the copy to the source afterwards.
- A copy holds each side's blocks at `free` v1, as an import does, or, for a card that is `free` v2 at the source, its 칸 list at `free` v2 with `back` `[]`. The media read policy is unchanged, since the list stays in `front`. A copy does not carry the public deck's image ([ADR 0107](adr/0107-store-media-in-a-private-supabase-storage-bucket-named-by-media-id-and-give-each-deck-an-image.md)).
- A copy owns its photos and sounds ([ADR 0113](adr/0113-copy-a-public-deck-s-photos-and-sounds-into-the-copier-s-own-media-under-new-ids-when-the-deck-is-copied.md)):
  - before its transaction, `addCards` reads each file the cards name from the owner's folder, passed in `FromCopy`, and keeps it on the device under a new media id in the copier's own media;
  - it queues each file for upload as the card holding it is written ([`media.md`](media.md)), and the copied block or 칸 names that id;
  - a file several cards hold is stored once. The files of a card skipped or merged as a duplicate are deleted from the device after the transaction, and every fetched file is deleted when the transaction fails.
  - A file the owner removed, or one the network fails to bring on 3 tries, leaves its block naming a new id no file holds, which the card draws as having no photo or sound. The copy still succeeds.
  - Every copy, a re-copy of the same deck included, makes ids of its own, and it keeps its files after the owner deletes the card or the deck stops being public. The media id is part of a card's key, so a re-copy into a deck finds no photo or sound card a duplicate.
- Any signed-in user may read, from the private `media` bucket, the image of a deck the server shows as public, and each photo and sound a live card of such a deck holds, on its front or back, and no other file of its owner's ([ADR 0112](adr/0112-store-an-audio-block-by-media-id-and-length-up-to-60-seconds-and-play-the-front-s-sound-once-as-a-study-card-appears.md)). A copy reads the cards' files this way. The browse screen and the preview draw no deck tile, so the app reads no deck image there yet.

### Reporting and blocking

- The preview's menu offers "노트 신고" and "이 사용자 차단".
- "노트 신고" asks in a sheet, "신고 이유", for a reason, inappropriate, spam, copyright or other, with "신고" as its one action and no cancel, and files it once; a second report of the same deck says "이미 신고한 노트예요".
- "이 사용자 차단" asks for confirmation, then blocks the owner and returns to the browse screen, which lists again without the owner's decks.

### Moderation

- A deck that three users reported is hidden by the server ([`server.md`](server.md)). Admins moderate on the web, in the admin area's 신고 and 공개 노트 pages: hide or unhide a deck, make a public deck private, remove a public deck from sharing for good with a reason, and dismiss a deck's reports, each after a confirmation and each recorded in the audit log ([ADR 0070](adr/0070-run-the-service-from-a-web-admin-area-whose-role-and-audit-log-live-in-the-database-and-whose-every-read-and-write-is-checked-there.md), [`web-admin.md`](web-admin.md)). Dismissing leaves a hidden deck hidden, and three new reports hide a deck again.
- A deck an admin made private reaches its owner's devices by sync like a private switch on another device: the server gives it an edit time of now, so it wins over an older edit ([`sync.md`](sync.md)). The owner can publish it again, unless it was removed from sharing: the server then refuses the publish, which leaves the deck private on the device and says why in the sheet ([ADR 0072](adr/0072-suspend-a-user-through-supabase-auth-s-ban-and-restrictive-write-policies-remove-a-public-deck-from-sharing-for-good-and-read-any-deck-in-the-admin-area.md)). A removed deck stays its owner's with its cards, and copies made before stay their users'.
- **Screening** ([ADR 0238](adr/0238-screen-a-note-by-rules-in-the-publish-note-function-keyed-by-a-hash-of-its-text-and-let-no-client-write-make-a-deck-public.md)). A note is checked by rules before it is public, and again after its owner edits a public note's text, which hides it until checked: personal numbers, links and contact prompts, repeated promotions and the operators' banned words, with no AI layer: a banned word is matched mechanically and the list holds certain terms only, and what the rules miss is left to reports ([ADR 0240](adr/0240-keep-note-screening-to-rules-and-let-reports-catch-the-rest-and-return-each-finding-s-field.md)). A refused note is private with the category and where it was found; a held note waits for an admin, who allows it or keeps it hidden; an admin's keep-hidden blocks the unchanged text from being published again. The admin list of users with violations on 3 or more notes is for the admin to act on and suspends no one.
- Nothing in the app moderates.

### Failures

- Each expected failure is a `SharingFailure`, mapped from PostgREST's codes as `sync` maps them ([`sync.md`](sync.md)): `SharingRejected`, `SharingOffline` (also no answer within 20 seconds), `SharingFailed`, and `DeckNoLongerPublic`.
- Screens show a `SharingFailure`, or a `DeckFailure` from the local write, as a localized message: in a snack bar for an action, in the sheet for a publish or a copy, and in place of a list. Any other error propagates.

### Interface

- Every string comes from the shared ARB set, in Korean and English. Icon buttons carry tooltips, headings are marked as headers, progress indicators carry a label, and a sheet's error is a live region.
- The screens follow [`design/`](design/principles.md) and are built from the shared components ([ADR 0021](adr/0021-type-and-spacing-scales-and-a-shared-component-layer.md)): browse rows are `AppListRow`s, the preview's cards one `AppGroup` of `CardBackRow`s that open nothing, the publish, import and report sheets `AppSheet`s, the block confirmation `showAppConfirm`, the chip `AppChip`, and each screen's or sheet's one primary action an `AppButton` at the bottom.

- `app/test/sharing/supabase_sharing_server_test.dart` — `SupabaseSharingServer` over a substituted HTTP client: a publish sends its created and updated times in UTC, truncated to the millisecond through `storedTime` as sync's pushes are ([ADR 0034](adr/0034-key-synced-rows-by-client-made-uuids-purge-tombstones-past-a-revision-horizon-and-index-each-query.md) §2), and no visibility, then asks `publish-note`; a private write sends `visibility = private` and no call; each state of `checking`, `held`, `refused` and `public` is answered with the layer and the findings (an unknown category reads as `other`, a finding without a card has none), and no state or an unknown one fails the publish; each status maps to its failure. A card is read from its 칸 list at `free` v2 and from its sides otherwise.
- `app/test/sharing/sharing_server_test.dart` — `SupabaseSharingServer` against the local stack `scripts/test-sync.ts` starts: publish, list, preview, copy count, report, block, and that sync never pulls another user's public deck. The stack runs no Edge runtime, so the file stands `publish-note` in with a substituted HTTP client: the owner's `request_deck_publication` with the owner's session, the screening's pass done by a write in the database container, then `my_deck_screening`. A note held for an admin stays held on the device through the sync that follows, and a deck public on the device and never synced is created private by sync, which then has nothing unsynced. Each step the file takes on the stack is bounded by `SupabaseSharingServer`'s 20-second request timeout, the bound past which the app counts the server as offline: every sharing and sync request, and each user's sign-up, which retries within that bound while Auth answers that the request may be retried. The file sets no bound over a whole test, whose duration is the sum of its steps and grows with the host's load (issue #78).
