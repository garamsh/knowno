# Server sharing

The server's side of sharing: public decks with their profiles, copies, reports and blocks, the screening of a note before it is public, the triage of reported notes, and the suspension of users and removal of decks from sharing.

## Current decisions

### Public decks

- `decks.visibility` is `private` (the default) or `public`; a public deck has `published_at`. `decks.description` is at most 300 characters. These sync like the deck's name ([`sharing.md`](sharing.md)).
- `decks.hidden` and `decks.copy_count` are the server's: clients read them and cannot write them.
- `public.profiles` holds one display name per user, 2 to 20 characters with no surrounding whitespace. Users insert and update their own; anyone signed in reads the name of a user with a visible public deck.
- `public.deck_reports` holds one report per reporter and deck, with a reason: `inappropriate`, `spam`, `copyright` or `other`. A user inserts a report only as itself, on a visible public deck of another user, and reads none back.
- A trigger hides a deck once three distinct users reported it, under an advisory lock on the deck seeded with 2, so concurrent reports are counted one after another. The lock's key hashes the deck's id as text, so the key a deck took before the ids were `uuid` is the key it takes now. An admin unhides it in the web admin area, which can also make a deck private and dismiss its reports ([`server-admin.md`](server-admin.md) §Admin area).
- `public.user_blocks` holds a user's blocks; users select, insert and delete their own.
- `list_public_decks(search, sort, page_size, page_offset)` runs as the caller and lists visible public decks not of a user the caller blocked, whose name or description holds the search ignoring case, newest first or most copied first, with the owner's display name and live card count. It returns each deck's id as `uuid`.
- `record_deck_copy(deck_id uuid)` runs as its owner: it returns false for a deck that is not visibly public, and otherwise true. A caller's first copy of a deck it does not own inserts a row in `public.deck_copies` and adds one to `copy_count`; a later copy by that caller, or a copy by the owner, changes neither (issue #67).
- `public.deck_copies` holds one row per deck and user who copied it, keyed by the two, so concurrent copies by one user insert one row and add one between them. Clients hold no privilege on it, and row-level security is on with no policy. Removing a row, with its deck or its account, leaves `copy_count` as it is.
- Copies made before the table existed were not recorded per user, so their counts stay as they were and later copies add to them. Migration `20261016090000_deck_imports.sql` is additive: it creates the table and replaces the function with the same signature, changing no row.
- Migration `20261019230002_name_public_deck_copies.sql` named copying a public deck "copy" ([ADR 0082](adr/0082-name-copying-a-public-deck-copy-and-keep-import-for-photo-import.md)): it renamed `deck_imports` to `deck_copies` with its keys and index, `decks.import_count` to `copy_count` with its check, and `record_deck_import` to `record_deck_copy`, recreating `list_public_decks`, `admin_public_decks`, `admin_deck` and `admin_user_deck`, which return the count, with the same bodies and privileges. It changed each copied card's `source` from `shared` to `copy`, so each such row took a new revision, its edit time kept; no other row changed.
- A deck is visibly public when it is public, not hidden and not deleted. No client write makes a deck public: §Note screening.

### Note screening

- **What it is** ([ADR 0238](adr/0238-screen-a-note-by-rules-in-the-publish-note-function-keyed-by-a-hash-of-its-text-and-let-no-client-write-make-a-deck-public.md)). A note is screened before it is public and again when a client edits its text. `decks.publication` is `private`, `checking`, `held`, `refused` or `public`, tied to `visibility` and `hidden` by the check `decks_publication_state`: `public` is public and shown, `checking` and `held` are public and hidden, `refused` and `private` are private. Clients read it and never write it.
- **The guard.** `private.guard_deck_publication` (before insert or update on `decks`) refuses a client's write that makes a deck public with `42501` `publication_requires_screening`, pins a public deck's `hidden`, `publication` and `published_at` against a client's write, and moves a public deck to `checking` when a client changes its name or description. A client is `authenticated`, `service_role` or `anon`; any other writer has `publication` derived from `visibility` and `hidden`. Statement triggers on `cards` do the same for a client's card insert or text change.
- **Owner functions.** `request_deck_publication(deck_id, description)` sets the description to the one given, trimmed, none when empty or null, and makes the deck `checking`, or `held` while a hold stands, and refuses a suspended owner and a removed deck; `my_deck_screening(deck_id)` answers its state, refusal category and findings.
- **Service functions,** executable by `service_role` alone and called by `publish-note`: `screening_due`, `screening_claim`, `record_screening` and `apply_screening`. Tables in `private`: `deck_screening` (the request time, the hold `reports`, `admin` or `ai`, the refusal layer), `screening_verdicts` (keyed by content hash and layer), `screening_terms` and `screening_violations`. No client role holds a privilege on them. `private.required_screening_layers()` is `array['rules']`. There is no AI layer ([ADR 0240](adr/0240-keep-note-screening-to-rules-and-let-reports-catch-the-rest-and-return-each-finding-s-field.md)): what the rules miss is left to reports, and a banned term refuses mechanically, the list holding certain terms only. The `ai` hold and the `ai` layer of a verdict or a refusal are kept and unused, so a model layer needs no schema change: a new ADR, its code in `publish-note` and `ai` in `required_screening_layers()`. A finding carries `field`, the path of the string its offsets index, null for the name and the description.
- **Admin functions,** each checking the role and recorded as [`server-admin.md`](server-admin.md) §Admin area states: `admin_screening_queue`, `admin_screening_findings` (answering `changed` and `unscreened` beside the findings), `admin_allow_deck`, `admin_keep_deck_hidden`, `admin_screening_terms`, `admin_add_screening_term`, `admin_remove_screening_term` (audited by id, never the term) and `admin_suspension_candidates` (users with violations on 3 or more distinct decks). `hide_reported_deck`, `admin_set_deck_hidden`, `admin_unpublish_deck` and `admin_remove_deck` keep `publication` consistent.
- **The sweeper.** `private.sweep_deck_screening()`, run each minute by the pg_cron job `sweep-deck-screening`, posts to `<project_url>/functions/v1/publish-note/work` through pg_net with `assistant_service_role_key` ([`server-assistant.md`](server-assistant.md) §Photo jobs, "Project address"), both Vault secrets, and does nothing with either missing or nothing due. `assistant_service_role_key` holds the value the platform sets as the functions' `SUPABASE_SERVICE_ROLE_KEY`, which on a project with the new API keys is the `sb_secret_...` secret key; the legacy `service_role` JWT is answered 401 by `/work`.
- Migration `20261110130000_publish_screening.sql` backfills `publication` on existing `decks` rows, so it was not additive, and the rule then in force required the owner's approval before merge; #867's comment records that the owner approved it on 2026-11-10. `screening_function_url` is replaced by `project_url`. **Revert:** `select private.revert_publish_screening();` and then `drop function private.revert_publish_screening();`.
- Migration `20261110170000_screening_finding_field.sql` replaces `private.screening_findings` so a finding carries `field`, and changes no row. **Revert:** `select private.revert_finding_field();` and then `drop function private.revert_finding_field();`, run once by the PM against production before `revert_publish_screening()`, which drops the function it restores.

### Report triage

- **What it is** ([ADR 0244](adr/0244-judge-a-reported-note-once-by-a-model-after-two-reporters-within-a-daily-spend-cap-ship-it-judge-only-and-let-it-hide-or-dismiss-only-by-an-admin-set-switch-with-every-action-undoable.md)). A scheduled function, `triage-reports`, judges a reported note once by a model; nothing is judged at publish. Its default is judge-only: it records verdicts and changes nothing.
- **Tables in `private`,** no client role holding a privilege on them:
  - `triage_settings`, one row: `mode` (`judge_only` or `acting`), `act_threshold` (0.9), `daily_cap_usd` (0.50), `batch_notes` (10), `daily_notes` (100), `sample_percent` (10), `undo_window_hours` (168), `undo_threshold` (0.2), `undo_min_actions` (5), `reporter_daily_cap` (20, 1 to 1000), `lease_minutes` (10), `max_failures` (3), `retry_minutes` (15), `resumed_at`, `paused_at` and `paused_reason`;
  - `triage_configurations`, append-only like `ai_configurations`: the cheap and strong tier's provider and model, each tier's USD per million input and output tokens, `escalate_below`, `payload_tokens`, `sample_cards` and the prompt; `triage_configuration_labels` names the `active` one and the draft, `test`;
  - `triage_verdicts`, keyed by content hash: `category` (`spam`, `ad`, `inappropriate`, `copyright`, `severe`, `other`, `ok`, `unjudged`), `confidence`, `passage`, `field`, `card_hash`, `tier`, `provider`, `model`, `configuration_id`, `tokens_in`, `tokens_out`, `cost_usd`, `escalated`;
  - `triage_actions`: the note, its content hash, `action` (`hide` or `dismiss`), category, confidence, model, reason, the archived reports of a dismissal, whether it is `sampled`, and when it was re-checked, by whom and whether the person agreed, and when it was undone and by whom;
  - `triage_appeals`, one row per AI action, keyed by `action_id`, with the admin's `undo_outcome`;
  - `triage_spend`, the cost ledger the daily cap counts: one row per provider call, with the tier, tokens, `cost_usd` and `estimated`, written by `record_triage_spend`;
  - `triage_attempts`, one row per note: the lease `claimed_at`, `failures` and `next_attempt_at`, bound to a content hash;
  - `report_log`, every report with `reporter_id`, `deck_id`, `reason`, `created_at` and `dismissed_at`, no foreign key to the deck; the daily report cap and the reporter weight read it.
- **Due** (`triage_due`): a live public note whose reporters weigh at least 2 (`reporter_weight`: 0.5 for a reporter with at least 5 reports in 90 days of which more than half were dismissed, else 1) and with no verdict for its current content hash, while an active configuration exists and the UTC day's ledger spend is under `daily_cap_usd` and its verdicts under `daily_notes`; a note that has failed `max_failures` times, or waits for `next_attempt_at`, is not due. At most `max_notes`, and with `severe_only` those with a `sexual` report. `triage_claim` returns null under the same conditions and while another worker holds the note's lease, and takes the lease (free or older than `lease_minutes`) by one atomic upsert; the lease is not part of `triage_due`, which may list a leased note.
- **Schedule.** `private.sweep_report_triage()`, run every 5 minutes by the pg_cron job `sweep-report-triage`, posts `{"severe": false}` to `<project_url>/functions/v1/triage-reports/work` when a note is due; an after-insert trigger on `deck_reports`, `private.triage_severe_report`, posts `{"severe": true}` when a `sexual` report is the note's second distinct reporter, and swallows any error of its own. A before-insert trigger, `private.log_report`, refuses a report past `reporter_daily_cap` a day (error 53400) and logs the rest; `private.log_report_dismissed` marks a report deleted while its note stands. `deck_reports.reason` is `inappropriate`, `sexual`, `spam`, `copyright` or `other`; `sexual` is accepted by the server before the app and web offer it. Both use the Vault secrets `project_url` and `assistant_service_role_key` ([`server-assistant.md`](server-assistant.md) §Photo jobs, "Project address") and do nothing with either missing.
- **Service functions,** executable by `service_role` alone and called by the function:
  - `triage_due(max_notes integer, severe_only boolean)` returns `deck_id` rows;
  - `triage_claim(deck_id)` returns `{hash, name, description, cards: [{hash, front, back}], reasons, reporters, findings, configuration}` or null, `findings` being the rules verdict's, `configuration` the active one with its prompt, rates and caps;
  - `triage_release(deck_id, failed boolean)` frees the lease and, with `failed`, counts a failure and sets `next_attempt_at` 15 minutes ahead, doubling per failure; returns the failure count;
  - `record_triage_spend(deck_id, content_hash, tier, provider, model, tokens_in, tokens_out, cost_usd, estimated)` writes a ledger row and answers whether the day's cap is still open;
  - `record_triage(deck_id, content_hash, category, confidence, passage, field, card_hash, tier, provider, model, configuration_id, tokens_in, tokens_out, cost_usd, escalated)` answers `changed` while the note no longer has the hash, `exists` when a verdict stands, otherwise `recorded`, or the action taken: `hidden`, `dismissed` or `paused`;
  - `save_triage_configuration(admin_id, cheap_provider, cheap_model, strong_provider, strong_model, prompt, cheap_in_usd, cheap_out_usd, strong_in_usd, strong_out_usd, escalate_below, payload_tokens, sample_cards)` appends the draft after the function's check calls parsed, refusing an `admin_id` that is no admin and a model that does not fit its provider (`private.model_fits`), and records `save_triage_configuration`.
- **The function's routes.** `POST /work` (`{severe?: boolean}`, the service-role key as bearer) judges the due notes, at most `batch_notes`, charging every provider call to the ledger as it returns (a reply without usage, or a call that may have run unseen, at its ceiling: every request byte a token in and the answer cap out, `estimated`), skipping the strong call once the cap is closed, and releasing a note whose judging failed or threw; each card, name and description is a JSON-encoded line inside `<note>` with `<` and `>` escaped, ordered name and description, cards matching the reasons' rule categories, other flagged cards, the sample. The two check calls of the settings route are not in the ledger; `POST /settings/configuration` (the same fields as `save_triage_configuration` without `admin_id`) takes the admin's access token, asks `admin_ai_session`, makes one check call per tier, and saves. Answers: `{saved: true, configuration_id}` or `{error}`: `bad_request` 400, `unauthenticated` 401, `forbidden` or `reauth` 403, `no_key` 409, the check's failure 422.
- **Acting** (`record_triage` calls `private.triage_apply`): only while `mode = 'acting'` and `paused_at` is null, it hides a note judged `spam` or `ad` with confidence at or above `act_threshold` when the note holds no hold (`hidden` and `held` with the `ai` hold), or archives and deletes the reports of one judged `ok` at or above it, while no `copyright` or `sexual` report exists. It never touches a verdict of `copyright`, `severe`, `inappropriate`, `other` or `unjudged`, and never unpublishes, removes or suspends. Each action records a `triage_actions` row and an audit row with `admin_id` null and `admin_email` `ai`, the action `ai_hide_deck` or `ai_dismiss_reports`, and the model, category, confidence and reason in its detail. `private.triage_check_pause()` sets `paused_at` with the reason `undo_rate` when the window's undone share passes `undo_threshold` with at least `undo_min_actions` actions; it runs before each action and after each undo.
- **Admin functions,** each checking the role and recorded as [`server-admin.md`](server-admin.md) §Admin area states, the shapes web (#888) and the app (#889) read:
  - `admin_triage_queue()`, one row per note with 2 or more distinct reporters: `deck_id`, `name`, `owner_id`, `hidden`, `publication`, `reporters`, `reasons`, `last_reported_at`, then the verdict's `category`, `confidence`, `passage`, `field`, `tier`, `model`, `cost_usd`, `judged_at` (null while unjudged), `action_id` (the standing AI action, if any) and `appealed` and `failures`; `sexual` first, then the latest report;
  - `admin_triage_actions(days integer default 30)`: `action_id`, `deck_id`, `name`, `action`, `category`, `confidence`, `model`, `reason`, `created_at`, `sampled`, `rechecked_at`, `recheck_agreed`, `undone_at`;
  - `admin_undo_triage_action(action_id)`, `undone`, `already`, `superseded` (a hide whose `ai` hold is gone; nothing changes) or `not_found`: it unhides a hidden note or restores the archived reports without the report cap, recording `undo_triage_action`;
  - `admin_triage_sample()`, the sampled actions not yet re-checked, in `admin_triage_actions`' columns, and `admin_recheck_triage_action(action_id, agreed)`, `rechecked`, `already`, `not_sampled` or `not_found`;
  - `admin_triage_settings()`, the settings row with `spent_today_usd`, `judged_today`, `actions_in_window` and `undo_rate`, and `admin_set_triage_settings(mode, act_threshold, daily_cap_usd, daily_notes, sample_percent, reporter_daily_cap)`, each null meaning unchanged, refusing a mode that is not one of the two, a threshold outside 0.5 to 1, a cap below 0 or above 1000, a daily notes over 10000, a share outside 0 to 100 and a report cap outside 1 to 1000, recording `set_triage_settings` with the new values; `admin_resume_triage()` clears the pause and stamps `resumed_at`, from which the undo window counts, recording `resume_triage`;
  - `admin_triage_agreement(days integer default 30)`: per category `compared`, the verdicts an admin has since decided on the same note, and `agreed`, those the decision agrees with ([ADR 0244](adr/0244-judge-a-reported-note-once-by-a-model-after-two-reporters-within-a-daily-spend-cap-ship-it-judge-only-and-let-it-hide-or-dismiss-only-by-an-admin-set-switch-with-every-action-undoable.md));
  - `admin_triage_appeals()`: `deck_id`, `name`, `owner_id`, `appealed_at`, `action_id`, `category`, `confidence`, `passage`, `field`, for appeals not yet resolved, and `admin_resolve_triage_appeal(deck_id, restore)`, `restored` (the undo), `not_restored` (an undo that answered `superseded`), `upheld` or `not_found`;
  - `admin_triage_configurations()`, each label's configuration with its prompt, rates and caps; `admin_activate_triage_configuration()`, under an advisory lock seeded with 7, refused while a provider has no key; `admin_clear_triage_test()`.
- **Owner functions,** executable by `authenticated`: `appeal_ai_hidden_note(deck_id)` answers `appealed`, `already` (for this standing action) or `not_hidden_by_ai`, the caller being the note's owner and the note hidden by a standing AI action; `my_triage_state(deck_id)` answers `{hidden_by_ai, appealed, resolved, category}` for the owner and null for anyone else, `category` being the `spam` or `ad` of the standing AI hide, null when none stands (migration `20261111130000_triage_state_category.sql`, which keeps the other three keys; **revert:** `select private.revert_state_category();` and then `drop function private.revert_state_category();`, before the revert below).
- Migration `20261111000000_report_triage.sql` creates the tables, functions, triggers and cron job, backfills `report_log` from the existing reports, widens the reason check of `deck_reports`, and replaces `admin_provider_keys` and `admin_remove_provider_key` so that the active triage configuration's providers count as in use; the function it ships spends money once an admin saves and activates a configuration, which is the Gate's cost case ([`server.md`](server.md) §Edge Function deploys), and it needs the owner's approval for the function's deploy. `triage_function_url` is replaced by `project_url`. **Revert:** `select private.revert_report_triage();` and then `drop function private.revert_report_triage();`.

### Suspension and removal from sharing

- `private.suspensions` holds each suspended user with the reason, who suspended and when; a user without a row is active ([ADR 0072](adr/0072-suspend-a-user-through-supabase-auth-s-ban-and-restrictive-write-policies-remove-a-public-deck-from-sharing-for-good-and-read-any-deck-in-the-admin-area.md)). `private.deck_removals` holds each deck removed from sharing for good, with the reason, who removed it and when. No client role holds a privilege on either.
- `admin_suspend_user` sets the user's `auth.users.banned_until` 100 years ahead, and `admin_unsuspend_user` sets it to null, so Supabase Auth refuses a suspended user's sign-in and refresh with `user_banned`. This is the only write to the `auth` schema in any admin function: none writes an email, a password, a phone, a metadata column or a `profiles` row.
- Restrictive policies on `decks`, `cards`, `reviews` and `card_states`, one per command a user may run, refuse a suspended user's writes through `public.is_suspended()`; the owner policies are unchanged, and reads still pass. `extract-cards` asks `public.user_suspended(user_id)`, executable only by `service_role`, before it counts a photo ([`ai-extraction.md`](ai-extraction.md)).
- `admin_remove_deck` makes a deck private with an edit time of now, as `admin_unpublish_deck` does, and records its removal; restrictive policies on `decks` keep a removed deck from being made public again, through `public.deck_removed_from_sharing(deck_id)`.
- The admin functions, each checking the role and recording itself as [`server-admin.md`](server-admin.md) §Admin area states: `admin_user_suspension`; `admin_suspend_user` (recorded as `suspend_user` on a `user`, with the email and the reason), which refuses the caller, an unknown user and a suspended one; `admin_unsuspend_user` (`unsuspend_user`); `admin_user_decks`, a user's live decks, private ones too; `admin_user_deck` and `admin_user_deck_cards`, any deck read-only with its removal; and `admin_remove_deck` (`remove_deck` on a `deck`, with the name and the reason).
- `admin_deck`, `admin_deck_cards` and `admin_find_users` stay in the database with no caller; dropping them is a non-additive change left to a migration the PM approves.
- Migration `20261019200000_admin_users.sql` creates the two tables, their indexes, the policies and the functions, and changes no existing row and replaces no existing object.
